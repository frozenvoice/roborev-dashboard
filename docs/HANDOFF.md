## Tasks checkpoint handoff

Tasks v1은 **Codex-only, job-level non-agentic** custom task surface다. Dashboard가 만드는 유일한 command는 exact `roborev run --agent codex --json`이며 사용자가 입력한 task는 argv가 아닌 exact UTF-8 stdin으로 전달되고 16 KiB byte limit을 갖는다. arbitrary shell/command, agent, model, reasoning, yolo/unsafe flag와 persistent task history는 제공하지 않는다. RoboRev jobs API가 launch receipt 뒤의 source of truth다.

Preview는 선택된 registered repository의 opaque identity, canonical path, current full HEAD, branch, exact v0.64.0 CLI executable/version, healthy same-version daemon, current binary binding과 safety를 fresh하게 확인하고 실제 executable/argv/stdin/mode/safety를 표시한다. global config file 또는 safety key가 unset이면 upstream safe default인 `false`로 허용하지만, `allow_unsafe_agents=true` 또는 `disable_codex_sandbox=true`이거나 config가 malformed/unreadable/type-invalid/unknown이면 fail closed한다. backend signed one-time TTL token은 task와 전체 repository/config/binding tuple에 묶여 confirmation에서 재사용·만료·scope drift를 거부한다.

확인 단계는 task global/repository/selected-repository leases와 Setup/runtime/mutation/Review/Rerun/Panel Refine/General Fix gate를 사용하고, HTTP disconnect와 무관한 server-owned context로 enqueue acceptance까지 실행한다. Generic frozen rerun endpoint/UI는 `job_type=task` 또는 `git_ref=run`을 거부하거나 숨기고 `phase=task-rerun-unsupported`를 반환해 Tasks safety preview를 우회할 수 없게 하며, Tasks v1 rerun은 지원하지 않는다. RoboRev v0.64.0의 internal `ensureDaemon` startup race와 config watcher hot-reload에 따른 TOCTOU는 upstream 경계로 남아 있으므로 실행 직전 fresh preflight를 유지하되 snapshot 보장으로 문서화하지 않는다. strict parser는 created `{job_id,job_uuid,git_ref:"run",status:"queued"}` 또는 skipped `{skipped:true,reason}`만 허용하며 child가 시작된 뒤 timeout/non-zero/truncated/malformed receipt는 `ambiguous enqueue`로 표시해 중복 재시도를 막는다.

Task history 화면은 `/api/reviews`의 `job_type=task` + `git_ref=run` rows와 existing ReviewDetail을 사용하고, SSE `jobs-changed`와 기존 4초 polling fallback으로 authoritative state를 재조회한다. Preview는 `POST /api/tasks/preview` JSON body를 사용한다. 이는 mutation이 아니므로 exact same-origin `Origin`, 또는 absent-Origin일 때 정확한 Fetch Metadata 조합을 body decode/preflight보다 먼저 검증하며, 실제 `POST /api/tasks` start만 same-origin/Host/CSRF mutation authorization을 거친다. confirm/submitting 중 composer 편집을 잠그고 one-shot submit guard로 double enqueue를 막는다. Windows direct CLI child는 bounded timeout/cancel을 유지하면서 upstream `ensureDaemon`이 시작한 daemon child를 `KILL_ON_JOB_CLOSE`에서 보존하는 `AllowDetachedChildren` 경로를 사용하며, `internal/process/runner_detached_windows_test.go`의 deterministic process-level parent-cancel/child-survival test로 고정한다. Dashboard가 offline daemon을 직접 시작하지는 않는다. deterministic fake process/HTTP/RoboRev fixtures만 자동 테스트에서 사용했으며 실제 quota-bearing Custom Task는 실행하지 않았다.

## General Fix checkpoint handoff

이번 checkpoint의 문서/구현 경계는 General Fix와 Panel Refine을 분리하는 것이다. Sidebar의 `Fix & Refine`가 full Panel Refine 화면과 General Fix를 소유하고, `Reviews`는 active 또는 `needs_attention`인 Panel Refine의 compact summary와 해당 화면 링크만 제공한다. General Fix의 대상은 selected registered opaque `repositoryIdentity`에 속한 terminal `status=done`, `verdict=F`, `closed=false`, `skipped=false` review인 single job 또는 panel synthesis parent뿐이며 member job은 영구적으로 제외한다. General `roborev refine`와 실제 `roborev fix`, 실제 multi-agent panel review는 이 handoff에서 실행하지 않았다.

공식 RoboRev v0.64.0 source 기준 exact command는 `fix --agent codex --quiet <job-id>`이며 `<job-id>`는 positive decimal positional ID다. upstream `fix`가 현재 checkout에서 실행되고 dirty/stale target을 자체 차단하지 않으며, stdout/stderr가 machine-readable 계약이 아니고 exit 0이어도 no-change/dirty 상태 또는 job close가 가능하다는 점을 Dashboard 정책에 반영한다. Dashboard는 preview token과 backend-generated exact argv를 confirmation에 제시한 뒤, 확인 POST에서 fresh authorization을 반복하고 typed builder로 argv를 재생성한다. current branch+target HEAD equality와 clean tree를 시작 조건으로 삼고, process-scoped async manager/cancel/shutdown, shared global/repository gate, bounded status/error, post-run same identity/branch + advanced HEAD + clean tree 검증, authoritative refresh를 요구한다. process restart resume은 지원하지 않는다. v0.64.0 fix가 commit 뒤 panel 없는 default review enqueue를 시도할 수 있는 부수 효과는 억지로 숨기거나 성공의 근거로 해석하지 않는다. 근거: [upstream fix source](https://github.com/kenn-io/roborev/blob/v0.64.0/cmd/roborev/fix.go), [assisted-refactoring guide](https://github.com/kenn-io/roborev/blob/v0.64.0/docs/guides/assisted-refactoring.md).

구현과 deterministic 검증을 완료했다.

- Backend: exact `fix --agent codex --quiet <job-id>` argv/positive-ID, single·synthesis parent 허용과 member 차단, done/F/`closed=false`/`skipped=false` 및 ownership, preview token과 confirmation-time fresh revalidation, stale/dirty/branch/identity conflict, global/repository gate, async disconnect independence, cancel/shutdown, bounded output/error, post-inspection HEAD/branch/identity/clean 계약을 deterministic fake로 검증했다.
- Frontend: Reviews compact Panel Refine summary와 Fix & Refine navigation, single/synthesis target selection, backend preview/argv confirmation, running/succeeded/failed/cancelled 상태, cancel/reload/authoritative refresh, ko/en 상태 보존과 390 px mobile layout을 검증했다.
- 실행 기록: targeted `internal/app`, `internal/roborev`, `internal/fixoperation`, `internal/operation`, `internal/refine` Go tests PASS; 전체 Vitest 7 files/170 tests PASS; `scripts/test.ps1` PASS(전체 Go suite + Vitest + production Vite build); `scripts/build.ps1`과 생성된 Windows EXE `--help` smoke PASS. 실제 RoboRev fix, LLM 또는 3-agent panel review는 실행하지 않았다.

## 결정

- production은 React assets를 Go binary에 embed한 단일 exe다.
- detail/prompt/log는 stable CLI를 사용한다. prompt/diff 없는 목록과 job ownership lookup, review enqueue, frozen rerun, panel members, health는 v0.64.0 daemon HTTP API를 version-gated로 사용한다.
- repository registry는 canonical Git root만 허용하고 runtime fresh inspection과 startup persisted-path inspection 결과가 expected identity와 일치하는지 같은 platform-aware 규칙으로 재검증한다. Frontend는 backend 제공 opaque identity만 비교한다.
- panel discovery는 v0.64.0에 enumeration API가 없어 typed TOML fallback으로 global/local map merge를 재현한다. registered root direct `.roborev.toml`만 지원하며, config는 플랫폼별 no-follow handle로 bounded read한다. direct config 없는 `.git` regular-file layout은 metadata를 확인하고, metadata 실패 시 global named panel discovery/mutation을 fail closed하며 actual linked worktree는 main-config 상속을 추측하지 않고 built-in `none`만 허용한다.
- panel preference는 Dashboard config에 repository identity별로 저장하되 current catalog를 매번 다시 authorization한다. malformed config는 fail closed한다.
- Panel Refine은 기존 Fix Prompt를 대체하지 않는 별도 자동 workflow다. backend state machine만 run을 진행하고, v0.64.0 fix adapter는 확인된 `roborev fix --agent codex --quiet <synthesis-id>` argv 계약을 사용한다. 전체 run과 각 enqueue/poll/fix에는 bounded timeout이 있다.
- General Fix는 Panel Refine과 별개인 process-scoped operation이며, terminal F single review 또는 synthesis parent만 대상으로 한다. exact v0.64.0 `fix --agent codex --quiet <job-id>`를 backend typed builder로 생성하고 preview/확인·fresh authorization·clean/stale/branch/identity gate·post-run HEAD advancement 검증을 거친다. panel member, 일반 `roborev refine`, arbitrary command와 browser가 만든 argv는 지원하지 않는다.
- Analyze integration은 introspection-only catalog/prompt adapter로 유지한다. type/prompt는 RoboRev source of truth이며 Dashboard가 결과 언어를 바꾸지 않는다. v0.64 agentic enqueue의 Edit/Write/Bash 실행, preview token, receipt, operation history, Analyze 전용 polling loop, 장기 repository lock 또는 자동 daemon start는 추가하지 않는다.
- Fix Prompt는 terminal F single/synthesis/individual member의 bounded `show --json` subset으로 로컬에서 결정적으로 생성하며 LLM이나 mutation을 호출하지 않는다.
- review list는 각 요청 완료 4초 뒤, 작은 `/api/runtime` health 상태는 각 요청 완료 10초 뒤 다음 poll을 예약한다. `/api/runtime`은 repository inspect/list를 수행하지 않는다. `status --json`과 `list --json`은 full prompt/diff를 포함할 수 있어 polling에 사용하지 않는다.
- `roborev init`은 post-commit hook과 daemon start를 함께 수행하므로 자동 호출하지 않는다. `.roborev.toml`을 직접 관리하고 manual panel review를 사용한다.
- 릴리스 exe는 embed된 frontend assets만 사용하므로 Go/Node.js/npm 없이 실행할 수 있다. RoboRev가 없는 Windows amd64 runtime은 Agents & Setup의 explicit confirmation으로 pinned v0.64.0을 설치하고 현재 process에 즉시 rebind할 수 있다. browser는 URL/version/hash/path를 선택하지 못하며 자동 update는 지원하지 않는다.
