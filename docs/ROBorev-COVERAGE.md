## v0.64.0 capability notes

- Dashboard의 recommended policy는 전체 Review/Panel/Panel Refine 계약이 검증된 exact v0.64.0이다. Windows amd64 ZIP의 official asset name, 16,325,029-byte compressed size, SHA-256 `157b008086a2ad1c107fe4aa70f172275400dd508c4c9761db2d604f9e56e056`, root `roborev.exe`와 user-level target을 source manifest에 pin한다. remote metadata가 다른 digest를 제시해도 자동 신뢰하지 않는다.
- 이미 발견된 supported binary는 재설치하지 않는다. explicit override와 newer/unknown/broken/blocked binary는 보존하며 자동 downgrade/replace하지 않는다. 설치는 PATH, `roborev init`, hook, agent, credential과 Windows 보안 설정을 변경하지 않는다.
- setup은 same-origin/CSRF/Host 보호를 받는 typed strict-empty API다. download/hash/archive/publish/probe/rebind/daemon-health를 bounded 단계로 수행하며 integrity와 unsafe archive 오류는 fail closed한다. Application Control은 exact Windows policy error만 `blocked`로 분류하고 우회하지 않는다.
- 실제 v0.64.0 health payload는 `healthy:true`, `uptime`, `version:"v0.64.0"`, `database`/`workers` components, `recent_errors:null`, `error_count_24h:0` shape로 확인했다. deterministic fixture가 bounded/malformed/trailing/oversized/unhealthy/unknown-field를 고정하며 `$schema`는 missing/임의 string을 허용하고 null/non-string을 거부한다. Stream Relay daemon-version mismatch도 계속 fail closed한다.
- `review`는 `--json`을 제공하지 않는다. upstream `/api/enqueue` response는 single job 또는 panel synthesis와 `member_job_ids`를 반환한다.
- 실제 v0.64.0 `/api/jobs` payload에서 `commit_subject`, `enqueued_at`, `started_at`, `finished_at`, `verdict: "P"|"F"`, `panel_member_name`, `panel_member_index`를 확인했고 HTTP fixture/UI test로 고정했다. Panel member 목록은 `panel_run` metadata query로만 polling하되 Dashboard endpoint가 opaque repository identity와 synthesis parent ID에 run/role/job identity를 bind한다. 선택한 member의 실제 저장 output은 panel-scoped detail이 같은 tuple과 Show response identity를 검증한 뒤 `show --job <id> --json`으로 lazy-load한다.
- `list --json`은 prompt와 diff를 포함한다. v0.64 daemon도 `omit_prompt=true`에서 queued/running prompt를 유지하므로 Dashboard adapter가 status와 무관하게 heavy fields를 제거한다. Lazy Prompt/Log authorization은 이 caveat를 metadata-only로 오인하지 않는다. Target fast path의 exact `id` query와 registered canonical `repo` witness query는 128-byte byte-at-a-time prefix parser로 `jobs[0].id` 다음 `repo_id`까지만 읽고 즉시 멈춘다. `FreshRegisteredPaths`는 초기 Registry snapshot의 각 root를 fresh inspect한 뒤 deleted/canonical-drifted root를 제외하고 sorted immutable paths를 전달한다. 200 parsed matching `repo_id` witness만 authorize하며 witness-local malformed/oversized/transport/non-2xx 오류(404 valid negative 제외)는 기록 후 다음 witness를 시도하고, cancel/deadline/binding drift는 즉시 중단한다. mismatch-only는 Forbidden, match가 없고 오류가 있으면 첫 witness 오류를 반환하며 owner 3xx는 redirect follow/body read 없이 처리한다. same-binding `/api/review` 또는 `/api/job/log` content fetch는 witness match 뒤에만 허용되며, witnesses는 한 15초 deadline 아래 순차 실행된다. foreign queued/running prompt bytes와 foreign content endpoint 호출은 authorization 전에 0이다. Panel member는 같은 repository의 atomic synthesis witness로 authorize한다.
- panel parent rerun은 `/api/job/rerun`에서 원본 member의 frozen target/config와 synthesis를 새 `panel_run_uuid`로 복제한다.
- Panel Refine은 Rerun same target/config가 아니라 매 iteration fresh HEAD의 새 panel review를 enqueue한다. iteration panel PASS 뒤 명시된 final panel을 검증하며, final panel F도 같은 fix budget으로 수정한 뒤 iteration panel부터 다시 시작한다.
- Panel Refine receipt와 `/api/jobs` polling은 job ID, panel run UUID, repo path, full git ref, branch, panel, synthesis role 및 panel job type을 일치시켜야 한다. 알려진 running 상태만 계속 polling하고, unknown/malformed status 또는 P/F 없는 terminal은 fail closed한다.
- Panel Refine run은 Dashboard process-scoped다. browser reload/reopen은 active run에 재접속할 수 있지만 process restart 뒤 자동 resume하지 않는다. shutdown은 active run context와 child process를 취소한다.

## Repositories v3C safe repository merge checkpoint

The v3C contract is a narrow duplicate-recovery operation, not a generic merge/delete tool. Exact upstream v0.64.0 exposes no daemon merge route; `repo merge --yes <source> <target>` is the only mutation transport. Upstream resolves both arguments path-first with exact name fallback, then `MergeRepos` consolidates source commits, review jobs and agent-hook snoozes in a transaction, deletes the source row, and preserves target name/path. It does not move filesystem/Git state, mutate Dashboard Registry, or return a machine-readable receipt.

Dashboard eligibility requires one fresh stale source row that is Dashboard-unregistered, `Lstat`-absent and has `jobCount > 0`, plus one target selected by opaque Dashboard repository identity that is freshly registered, canonicalized and also exactly one RoboRev inventory row. Source/target counts, names/paths, fallback keys, command and runtime binding are token-bound; count drift is a 409 and does not launch a process. Source queued/running safety is fail-closed: a bounded typed stream of parent jobs is reconciled with panel summaries and the source inventory represented-count; incomplete coverage, malformed/count-mismatched evidence, panel members not represented by parent summaries, or any active source row rejects the operation. Target inactivity is not a required policy condition because upstream merge leaves target-owned jobs untouched.

Confirm uses the existing shared two-resource repository lease with a peek → release store lock → acquire source/target Gate → release Gate lock → claim token order. Gate busy preserves the token. The one shell-free process uses `repo merge --yes` with exact source/target paths and empty CWD. Once started, only one authoritative readback can produce `merged`: source absent, target unique, target name/path preserved and target job count at least `S + T`. All other started outcomes are `unverified`, with no retry or rollback. Delete remains unsupported; Registry, selection, registration/switch, filesystem and Git semantics remain unchanged.
